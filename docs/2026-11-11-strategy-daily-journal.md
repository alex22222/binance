## 运行方式

```sh
npm run strategy:daily
npm run strategy:daily -- --status
```

推荐由 `binance-agentic-strategy-daily.timer` 每天 UTC 23:35，即北京时间次日 07:35 触发。`Persistent=true` 会在恢复后采集当时的一天，但不会补写停机期间的历史。当天重复运行不改第一份成功归档。

任务只读取已保存的报告、策略配置、持仓状态及成交日志；在自己的目录建立交易索引缓存，不改原始文件、既有交易索引或研究报告。systemd 禁止网络和钱包目录访问，仅允许写自己的归档目录。没有新增付费 API、LLM 调用或 Codex 周期任务。

首次部署必须先创建 `state/strategy-daily` 并归属 `binancebot:binancebot`、权限 `0750`；`flock` 和 systemd 的 `ReadWritePaths` 在 Node 脚本执行前就需要目录存在。之后才安装、启用新的 service / timer。当前工作区还有其他未提交任务，不能全量发布；实盘身份包含源码哈希，后续应按隔离只读发布流程评审依赖，不能直接覆盖生产 `src/` 目录。

## 固定评分：evidence-tracking-v1

这是证据跟踪质量评分，不是收益打分、投资评级、盈利概率或实盘资格。不同来源之间不做综合排名，更不会据此自动切换或下单。

| 维度 | 满分 | 固定口径 |
| --- | ---: | --- |
| 数据时效 | 30 | 数据 / 估值年龄不超过 24h 为 30，24–72h 为 20；超过 72h、未来日期、缺少日期不出总分 |
| 样本积累 | 25 | `floor(min(25, 已平仓或标注样本数 / 20 × 25))`；20 只是显示刻度，不表示统计充分 |
| 成本完整度 | 20 | Paper 有有限非负记账费用、退出费用和模型净损益时为 20；Live 原始成本未重审为 10；历史有往返成本假设为 10；Shadow 卖出费用不完整为 0 |
| 内容可追溯 | 25 | 有保存来源的 SHA-256 内容哈希为 25；不意味着规则身份已独立绑定或研究合格 |

无数据、读错、未开始、过期、未来时间、无样本或不完整均显示“未评分”，不是零分。只有初始化资金、尚未到首个决策期的 Paper 不是运行证据，不给 75 分；采集失败不能靠刷新 `updatedAt` 变成新鲜市场证据。持仓使用 `markedAt`；Shadow 从原始标注结果提取每策略最后标注日，不能用报告重写时间替代。

策略目录 / 运行身份只作采集时观察，不把它倒填为旧证据的生产者身份；缺生产者绑定的 Paper 明确保留警告。

## 损益口径

- Live：使用完整交易索引内已确认、按订单去重的卖出净损益。浮动损益另列，不计入此日差；没有完整资本净值，因此不算实盘日收益率。
- 周频 / 频率 Paper：以假设立即退出、扣模型退出成本后的净值计算累计净损益；两端净值有限有效且前一日净值大于零时才算快照间收益率。当前净值真实归零时允许显示 −100%。
- 海龟等固定名义 Paper：已实现净损益加持仓假设退出净损益；不杜撰资本净值或组合收益率。
- 历史 / Shadow：不生成每日交易损益；多个 Shadow 窗口取最大样本数显示，不相加当独立交易。
- 日差只在相邻北京采集日、同一账本系列、两端证据有效时计算。首日、断档、费用 / 规则身份变化不给日差。开平仓本身不会因持仓派生费用字段改变而被当成换版。
- 累计平仓数回退时标记账本不完整，不把日志截断、索引重建造成的历史利润消失记成今日亏损。
- 晨间快照之间的变化不等同自然日或美股单一交易日；没有执行 / 交易不应被包装成新样本。

## 归档完整性

每份归档带内容哈希。用独占临时文件和硬链接发布首份文件，避免同日重复或并发覆盖；读取时重新计算哈希并校验日期，不合格文件从展示中排除并报告错误。最近 90 个采集日供页面查看，磁盘上的旧记录不自动删除。没有凭空回填旧日记。
