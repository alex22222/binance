# BTC 风控雷达

日期：2026-10-01，P0 口径与 P1 布局更新于 2026-10-23。来源：claude.ai 看板「BTC 风控雷达」及其定时任务「BTC 风控雷达更新」。

## 迁移内容

- 页面：Dashboard 菜单「BTC 风控」，路径 `/btc-radar`，需要登录。按「市场背景、慢趋势、账户风险」三层组织，顶部提供锚点导航与账户高危/失效直达提示。原始指标优先，实验压力指数、模型解释与候选观察默认折叠；持仓标尺与只读预览保留。见 [P1 布局验收](2026-10-23-btc-radar-p1-layout.md)。
- 数据：`GET /api/btc-radar`（需要登录）读取 `state/btc-radar/latest.json` 和 `history.json`，页面每 60 秒刷新一次。
- 计算：`scripts/run-btc-radar.mjs`，由 `binance-agentic-btc-radar.timer` 每 4 小时运行（北京时间 00:43、04:43……20:43，与原定时任务同一时刻）。
- 模型：`pressure-v2-no-touch-probability`。保留原 Python 移植的五个因子公式及取整测试，但移除 Polymarket 触价因子的评分，将剩余相对权重归一化；不再宣称整体输出与旧 Python 一致。新旧评分走势不连线比较。见 [P0 修复记录](2026-10-23-btc-radar-p0.md)。

## 参考指标（只展示，不计分）

| 指标 | 显示位置 | 来源与口径 |
|---|---|---|
| RSI(14) 日线收盘 / 含当日盘中 | BTC 技术面 | OKX BTC-USDT UTC 日线，最近 300 根，Wilder 平滑。"收盘"只用已收盘 K 线，"盘中"包含当天未收盘的 K 线 |
| 恐惧贪婪指数 | 衍生品与情绪 | alternative.me 每日数值与分级（极度恐惧、恐惧、中性、贪婪、极度贪婪） |

两项都不进入因子分和综合分。取数失败时沿用上次的值并标注；从未取到时不显示，也不会让评估失败。不同网站的 RSI 读数常相差几个点，主要差在是否计入当天未收盘的 K 线，以及日线按 UTC 还是北京时间收盘。

## 趋势状态（200 日均线）

- **规则**：OKX BTC-USDT 已收盘的 UTC 日线，收盘价高于 200 日均线 3% 以上为「多头环境」，低于 3% 以下为「回避环境」，在 ±3% 之内维持原状态。只看已收盘的日线，盘中波动不会触发切换。
- **含义**：回避环境只表示不持有多头，不是做空信号。调研中，做空方向的规则在 2022 年以后都没有通过检验。
- **依据**：见 `docs/2026-10-06-btc-strong-signal-research.md`。2022 年以来按此规则持有现货（次日执行、含手续费），最大回撤 −39%；一直持有为 −67%。约每年切换 3 次。回测脚本 `scripts/btc-signal-study/robust.mjs` 与线上共用 `src/btc-trend.mjs`。
- **推送**：状态切换时单独发一条飞书，附上雷达评分、恐惧贪婪、日线 RSI、资金费率作为参考，并注明这些参考在回测中没有稳定预测力。部署后第一次读到的状态只记录、不推送。推送失败时，下一次评估用同一个消息 ID 重试。
- **数据窗口**：每次取最近 300 根日线，算出约 100 天的状态。「状态开始」只在这个窗口内能看到切换时才显示。

## 观察模式（只记录，不推送）

调研中没有通过 2022 年以后检验的六条候选信号，由服务器每天按 UTC 日收盘检查一次：

- **趋势延续 · 做多 / 做空**：价格同时在 20/50/100/200 日均线之上（之下），4 周涨跌同向，资金费率不过热（不为负），恐惧贪婪不在反向极值，美元和实际利率的 3 个月变化不逆风。
- **极端反转 · 做多 / 做空**：7 天内出现极度恐惧（贪婪），资金费率为负（年化 ≥30%），价格 3 天内收复（跌破）20 日均线。
- **30 日资金费率转负**和**资金费率过热（7 日年化 ≥30%）**。

记录方式：

- 每次触发记为规则首次成立的那一天，同一规则之后 14 天（资金费率转负为 30 天）内不重复记录。
- 从次日收盘起计算 7、30、90 天的涨跌；资金费率过热另外记录 30 天内是否跌超 20%。
- 页面把观察开始后的结果和同期随机日子比较。到期的触发满 10 次才给出 p 值。某条规则要积累到这一步、并且明显好于随机，才值得考虑改为推送。
- 第一次运行时数据窗口内已有的触发只作参考，标记为「观察开始前」，不计入观察结果。

数据：OKX 最近约 100 天的资金费率、alternative.me 最近 100 天的恐惧贪婪，以及 FRED 的美元指数（DTWEXBGS，按周发布）和 10 年期实际利率（DFII10）。这些来源取不到时，只影响观察模式，评分和趋势状态照常更新。

规则与 `scripts/btc-signal-study` 的回测共用 `src/btc-observe.mjs`。`scripts/btc-signal-study/parity.mjs` 用调研数据核对过：每日输入与回测完全一致，六条规则的触发日期也完全一致。

## 持仓风险测算与拖动预览

2026-10-09 多空扩展实现与生产证据见 [空仓和网格接入记录](2026-10-09-btc-radar-short-support.md)。三类持仓通过各自接口读取，不合并均价或收益，页面可以切换详情。网格不能用普通账户持仓为空判定无仓，也不能套用马丁格尔补仓公式。

空头价格上涨是亏损方向，价格止损在上、止盈在下；不提供未来止盈/止损概率。持仓评级优先检查强平是否先于或等于止损、距强平是否不足 3%/5%，再看止损距离。未知或旧持仓不显示为安全；即使绿色也只是距离参考。综合评分仍是未验证的 BTC 下跌压力，不是空头风险分或自动做空指令。普通永续与网格只按固定当前仓位测算，强平价直接取 OKX，不预测未来挂单、网格交易或资金费，因此不是最大亏损。

- **风险测算**（持仓面板下方）：止损触发时的亏损（先成交的补仓单计入在内）、止盈触发时的盈利、补仓全部成交后的强平价估算、打平所需的止盈比例；后者仅是损益比例，不是预测胜率。旧持仓不提供退出测算。
- **拖动预览**：在标尺上拖动「止损」「止盈」，或用键盘聚焦后按方向键（每步 0.1%，PageUp/PageDown 每步 1%，Esc 恢复），只在页面里重新计算，不会修改 OKX。服务器只有只读 Key，页面没有任何修改策略的接口。
- **总资金**：在页面输入后保存到服务器 `state/btc-radar/settings.json`，只用于计算亏损和盈利占总资金的比例。
- **补仓计数**：OKX 的 `fillSafetyOrds` 包含手动加仓。雷达改为读取本轮订单（`tradingBot/dca/orders`），只统计自动补仓，并取剩余补仓挂单作为阶梯；订单接口不可用时按 `fillSafetyOrds − fillManualOrds` 估算，页面提示阶梯数据不完整。
- **估算口径**：吃单手续费 0.05%、维持保证金率 0.4%，未计滑点；强平价估算假设每笔补仓按杠杆增加逐仓保证金。

## 与原定时任务的差异

- **不再依赖大模型。** 数据采集和评分都是确定性的代码；原任务每次运行都由 Claude 调用工具、组装输入。
- **持仓与舆情需要 OKX 只读 API Key。** 未配置时持仓显示"未接入"，舆情一项按中性计分（对综合分影响最多约 ±2 分），页面明确标注"未接入"。
- **Polymarket 只展示原始报价。** 排除已结算、关闭、失效和过期合约；同价位优先最新创建窗口，无法区分的重复合约不合并。不使用插值，不把日历区间内曾经触价解读为未来触价概率，也不把它转换为交易胜率。
- **年内降息概率**统一按"1 − 年内零次降息的概率"计算；取不到时用下次与下下次议息降息概率中的较大者，与原任务的兜底规则一致。
- **数据源失败**：评分所需来源只能沿用五小时内成功采集的缓存，并明确提示；缓存已过期则本次评估失败，不重打新时间戳。API 与浏览器独立检查快照及最老评分输入的五小时有效期，过期返回 `STALE`、隐藏当前分数与风险结论；相同响应、后续网络失败均不能保留正常结论。仅参考的数据可保留旧证据并提示，不用于当前持仓测算。五小时是四小时任务的宽限，不是行情实时性保证。
- **提醒**只在以下情况通过飞书发送：综合等级升高；持仓接近强平、止损不先于强平或接近止损（按真实原因描述）；自动补仓次数增加；止损消失；策略结束或改为跟踪新的策略；BTC 较上次评估涨跌超过 4%。不再每次都推送"例行更新"。旧持仓不用于发送变化提醒。200 日均线趋势状态切换时另发一条，见上文。

claude.ai 上的原看板和定时任务没有改动，仍在运行。确认服务器版正常后，可以自行在 claude.ai 停用原定时任务，避免重复提醒。

## 配置 OKX 只读 API Key

1. 在 OKX 创建 API Key：权限只勾选「读取」，IP 白名单填服务器 IP。
2. 在服务器上把 Key 写入单独的文件，不要放进 `/etc/binance-agentic-stock-bot.env`：

   ```bash
   sudo install -m 640 -o root -g binancebot /dev/null /etc/binance-agentic-btc-radar.env
   sudoedit /etc/binance-agentic-btc-radar.env
   ```

   字段见 `deploy/binance-agentic-btc-radar.env.example`。下一次运行自动生效，不需要重启服务。

3. 立即验证：

   ```bash
   sudo systemctl start binance-agentic-btc-radar.service
   journalctl -u binance-agentic-btc-radar.service -n 5 --no-pager
   ```

   日志里 `okxConfigured` 为 `true`、`position` 有值即表示接入成功。

雷达只发送签名的 GET 请求，客户端没有下单、改单、停止策略的能力。

## 文件

- `state/btc-radar/latest.json`：最近一次评估。
- `state/btc-radar/history.json`：评分走势，保留 60 天，页面显示最近 180 次。
- `state/btc-radar/inputs.json`：各数据源最近一次成功的原始输入，用于失败时沿用。
- `state/btc-radar/state.json`：正在跟踪的策略 ID、最近一次提醒的结果，以及最近一次已推送的趋势状态（`trend.notified`）。
- `state/btc-radar/observations.json`：观察模式的开始日期、各规则已检查到的日期、全部触发记录及其后续涨跌，以及观察开始后的日收盘价。
